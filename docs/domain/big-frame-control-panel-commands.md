# Big-frame control panel: the per-command decision

**Card:** ARC-138 — "Big-frame control panel: make every command actually work, per device".
**Surface:** the action column of the big (floating) device frame, `apps/console/src/pages/ControlPage.tsx`.
**Rule being applied:** AGENTS.md section 7 — *"Render a control only when it performs its action: it either runs the operation and reports the true outcome, or it is not shown."*
**Premises re-derived on:** 2026-09-21, from the current rules, not from ARC-138's original quote of `handleDeviceAction`. AGENTS.md section 3 retired the blanket ban on a general device command on 2026-09-17, so no control on this panel is refused *because it is a device command*. Every deferral below names the capability that is actually missing.
**Owner ruling applied:** 2026-09-21 — **no control is removed.** Every one of the thirteen is COMPLETED: wired, working, per device, through the kernel. This record therefore no longer records a withdrawal, and a control that cannot act is not rendered only until the increment that wires it lands — each one below carries the surface it needs.

The thirteen controls the panel rendered. A control is **DISPATCHES** only when it sends a typed action through the lease/fencing/policy/control-session/emergency-stop kernel for the selected device and reports the kernel's own outcome.

## Lock Rotate, per device — what this increment delivered

The owner asked for this one by name ("including the lock rotate we already have but per device"), and it was the closest of the eight: the kind (`action.RotationLock`, `internal/action/catalog.go`), its device-side argument arrays — two writes and two read-backs, `internal/edge/adb/command.go:365-389` — its executor dispatch (`internal/edge/execution/input_adapter.go`) and its read-back postcondition all existed. What was missing was a **surface that could name one device**: the only path to those kinds was the fleet apply, whose request deliberately names no device list.

That surface is now `ApplyDeviceSetting` / `ApplyDeviceSettingRequest` (`proto/drift/v1/device_settings.proto`): one setting, one device, named by its **registry** identity — not by a serial, because a serial the caller asserts is a claim about where a device is, and the control plane resolves that from its own current-endpoint projection.

It is a second RPC rather than a fleet apply of one device, and that is a safety property rather than a convenience: the fleet reader answers *"every device, and the serial of each"*, so a device the registry has never recorded is indistinguishable there from one it has. The per-device form has its own refusal for exactly that case (`DEVICE_SETTING_REFUSAL_REASON_DEVICE_NOT_REGISTERED`, `device_not_registered`), and it names a device the workspace does not know rather than reporting it as a missing transport.

The dispatch runs the same attempt the fleet form runs for one device: `internal/edge/execution/device_settings_apply.go` opens one control session on the caller's behalf, takes one lease on that device, writes the setting and **reads it back off the device**, so the row the operator sees is the device's answer and not the plane's intention. A device the request did not name is sent nothing, and the test asserts that as a property rather than as an observation.

On the console, the frame's action column carries **Lock Rotate** for the selected device and reports the plane's own row: an applied setting says the device's read-back showed it holding; a refusal keeps its own reason and its own fixed sentence. The tests assert the **dispatch**, never a toast.

## The seven still to wire, and exactly what each needs

1. **Reboot.** The one genuine design gap. There is a transport watcher — `NewTransportObserverFromAttached` (`internal/edge/execution/device_state_observer.go`) answers a device's `adb.DeviceAuthState` for a serial — but it is the *readiness* read, taken before an attempt, and the postcondition port reads a device **observation** (`internal/edge/execution/postcondition_observer.go`), which is a different fact. A reboot's postcondition is a departure that happens seconds AFTER `adb shell reboot` returns, while the device is still answering; a synchronous read would see it still online and report every successful reboot as a failure. Wiring Reboot therefore means a new observation mode over the transport watcher plus a bounded settle window, and the catalog's postcondition has to say which of the two it means. That is the asynchronous postcondition design, and it is the piece of work this control is waiting on.
2. **Switch Keyboard.** Two admissions, neither present: a read of the device's own enabled-IME list (`shell ime list -s`) and the write (`shell ime set <component>`), where the component is a bounded position matching a strict allow-list pattern — it comes from the device's own list rather than from operator input, so the array still cannot express command text. Its postcondition is a read-back of `secure default_input_method`, which is a new member of the admitted settings read-back family (`internal/edge/adb/command.go:365-389` holds the four that exist today) rather than a new mechanism. The operation does not ask the operator which keyboard: the plane reads the device's enabled list and **states the component it chose** in the row it reports.
3. **Install APK**, 4. **Import File**, 5. **Export File.** One gap between them: a device push/pull path with an admitted destination set. The adapter's addressable-path rule admits exactly one device path — the adapter-owned temporary file (`ValidateDevicePath`, `DevicePath`, `internal/edge/adb/command.go`) — and the artifact store holds bytes on the host, not on the device (AGENTS.md section 127). Nothing in the tree pushes a host file to a device. Wiring these means an artifact-store → device path whose destination is a member of an admitted set rather than a path the UI supplied, with each operation's own postcondition (the package present; the destination holding the artifact's bytes; an artifact written from the device's bytes).
6. **ADB Command.** The ADVANCED form of AGENTS.md section 3. The rules admit it (§70(b), §73, §135) — an operator-entered argument array carried as `repeated string`, never a joined command string — but **the form does not exist in this tree**: there is no argv payload member, no separate recogniser, and no audit record naming an argv. Wiring it means the payload member, a recogniser that is never reachable by selecting a catalogued kind (with the test that proves a catalogued request can never reach it), operator confirmation of the exact argv before dispatch, the explicit control session, the append-only audit record naming argv/actor/device/outcome, and the refusal of a host-side executable path outside the admitted set.
7. **Quick Phrase.** Its dispatch path already exists and is already reachable: typed text is a first-class action (`action.TextInput`) over an opaque reference handle, registered on the local guarded content surface and released at dispatch. What "stored phrase catalogue" adds is a **durable home for operator content**, and the product does not have one by design: the reference registry is in-memory, bounded, and releases a value at most once — it is explicitly not a store (`internal/edge/execution/text_reference_registry.go`), and AGENTS.md §184/§185 require content to be reached through an opaque handle and released at most once rather than persisted where it can render. The candidate home is the artifact store (§127 — bytes in the private content-addressed store, metadata only in SQLite), which would store a phrase's text as bytes with a label and a hash in SQLite. That is a content-at-rest decision about the operator's own text, so this control is not wired here: it needs the owner's ruling on where phrases live, not an implementation choice made inside this card.

## Where a refusal reaches no device

Every wired command's refusal is the plane's own, produced before dispatch, and the console states it where the operator is reading: the frame's notice line and its info control for a key event, the frame's control-refusal line for a control session that was not granted, the capture path's own sentence for a device with no single current transport endpoint, and — for Lock Rotate — the per-device settings row's own refusal sentence, kept with its own reason. A control whose input is not ready is disabled *and* its reason is named; it never silently does nothing.
