# Drift Next — Coding and Architecture Guide

This file defines how Drift Next code is designed, implemented, tested, and evolved. Keep it current when a reusable coding, architecture, security, reliability, testing, or accessibility standard changes.

## 1. Engineering principles

- Prefer the simplest design that satisfies a current requirement. Do not add services, queues, caches, abstractions, or dependencies for hypothetical scale.
- Design around cohesive domains and explicit boundaries. Keep UI, application/service logic, persistence, device execution, and external integrations separate.
- Make state changes explicit, validated, observable, auditable, and testable.
- Favor deterministic behavior, typed contracts, explicit failure modes, and safe defaults.
- Keep changes focused. Do not mix refactors, dependency upgrades, generated-code churn, and unrelated behavior changes without a clear reason.
- Preserve reversibility: version interfaces, use forward-only migrations, retain enough evidence to explain outcomes, and prefer incremental migrations over rewrites.
- State a capability the plane does not perform as absent, and never carry it as code nothing can reach, a wire field that lands on a different feature, or a console answer the plane cannot give. Unreachable code that looks like a capability is worse than no code, because the next reader — and the mock, and the reviewer — counts it as delivered. A skeleton spread across layers is retired deliberately in ONE change that names the decision which retired it, and the domain document says "not implemented" where it would otherwise describe an engine that exists. Where a surface offers what the plane cannot do, the fix is in the surface's own vocabulary: a console view type carries only the values the plane can produce, so an answer no plane can give is a type error rather than one client's private word. One exception, and it is the reason the proto is not touched here: PUBLISHED wire vocabulary keeps every number even where nothing reaches it yet (§2), so a state nothing reaches is reported as unreached — never quietly pruned, and never quietly counted as delivered.

## 2. Application architecture

```text
React/Vite operator UI
    -> narrow typed local API / IPC
    -> Go application service
    -> SQLite + artifact store + workflow runtime + device/runtime adapters
```

### Boundary rules

- The UI renders state and requests typed intents. It does not implement authorization, workflow execution, persistence, lease decisions, or device protocols.
- Application services own use cases, authorization/policy decisions, transaction boundaries, audit records, and orchestration.
- Repositories persist and query domain state. They do not contain UI behavior, transport behavior, or device-protocol logic.
- Adapters isolate infrastructure: SQLite, filesystem, HTTP/Connect, Tauri IPC, clocks, IDs, and future device integrations.
- Domain code must not depend on React, Tauri, HTTP handlers, SQL driver types, or device-library details.
- Prefer dependency injection through constructors. Avoid global mutable state, hidden singletons, and implicit environment reads deep in domain code.

### Domain rules

- Separate stable device identity from mutable endpoint/transport identity.
- Record a transport (USB or TCP) as a fact when the device is observed, and read it back from the record. Decide it once, at the record boundary, from the observation's own transport address; never let a reader — a projection, a handler, or the console — rebuild it from the shape of an endpoint address, because a reader that reconstructs it can report a transport nobody observed. An observation whose transport is unknown is reported as unspecified, never guessed into one of the two, and the transport is a property of the transport rather than a device lifecycle state.
- Derive a device's status from observation facts, never from a stored lifecycle column. A device has no lifecycle beyond its identity and its observation history, so the wire status reads the transport it was last observed at and what THAT transport reported about the device, and reports a device nobody has observed as unspecified rather than online: fail closed, and keep "never observed" distinguishable from "observed before, not observed now". An attached device that cannot be used is its own reading and not "offline": a device whose transport reported it as present but unauthorized, and one this host may not open, are both attached and both unactionable, and each names the one thing that fixes it — the device's own display, or the host's permission rule. A departure is recorded as an observation fact about the transport that left — the endpoint record it ends stops being current — never by refreshing the device's last positive observation and never by deleting the device, so a device that returns resolves to the same identity while one that is gone stays distinguishable from one that was never seen.
- Treat a scan as an observation, not as a registration step: a bounded Network Profile scan upserts each observed serial into the canonical `devices`/`endpoints` registry and returns it immediately. There is no candidate queue, no approval transition, and no separate registration or provisioning flow.
- Carry every observation fact a surface can hold onto the wire vocabulary that surface publishes, and extend the contract additively when the fact has no counterpart there: a link state this plane has recorded has to reach a consumer as itself, because a state that arrives as UNSPECIFIED tells a consumer "unknown" about a transport this plane had just read — which is how a `no permissions` transport, the host-side condition an operator fixes on the host, became indistinguishable from a link nobody had read (ARC-196's F2). Add the value; keep every published number and never reuse a retired one; a consumer that switches exhaustively on the enum is what turns the omission into a build failure instead of a silently wrong reading.
- Name a scan's target explicitly and never resolve one target into the other: a scan observes either a saved Network Profile or a range the operator entered. An entered range is a scan target rather than saved policy, so it is bounded by the same check a saved profile is and scanned by the same scanner, but the run it opens records no profile reference, and nothing is looked up, created, or reported as the profile that happens to bound the same addresses.
- Route every observation through that one serial-keyed upsert, whatever observed it: an arrival a post-launch watcher reports enters the registry by the same path a scan uses and opens no scan run, so a device seen on a second transport resolves to its existing identity instead of minting a second one. Match that upsert on the serial the DEVICE reports about itself whenever it reports a usable one, and never on the transport alone: adb names a TCP device by the address it answers on, so a serial taken from the transport changes with every new lease and re-registers one device as a second row (45 device rows for a fleet of about 22, the same unit drawn twice at two addresses), while the serial the device reports for itself follows it. The reported serial is a MATCH KEY, not a primary identity: the opaque device id stays the identity, the transport stays the mutable fact, and an observation that reported no usable serial — a fake device, a transport adb lists as offline — keeps resolving by its transport exactly as it did before. Learn the serial on the row an observation resolves to when that row holds none, so a fleet registered before this rule adopts it on its next observation instead of needing a backfill.
- Reconcile a duplicated identity by merging it, never by deleting it: where one unit is already registered as two device rows, a repair migration folds the duplicate's endpoint rows onto the canonical row — re-pointed, never rewritten, so every observation keeps its own transport, serial and time — retires the duplicate row in place because the audit that proves how it was created references it, and records the reason against both rows. Re-pointing an endpoint onto a row that already holds a current endpoint means settling which transport the unit was last reachable at FIRST: the unit's most recently observed current endpoint stays current and the others are superseded at that instant (the unique index allows one per device, so the order is not a preference), and a unit with no current endpoint keeps none, because a repair has no observation to invent. Group the rows the registry named after the device by that name and pick the canonical row by the serial the device reports for itself when it is known, by the most recent observation when it is not; reconcile a row the registry named after its transport only where the fleet's own record names the unit it belongs to, since over-merging moves one unit's history onto another unit's identity — the defect being repaired.
- Treat a device's own report of who it is as evidence to be validated at the boundary that reads it: the read is a fixed, allow-listed argv, the answer is bounded and pattern-checked, a sentinel or unusable answer is treated as no answer, and the persisted column is unique per workspace so two rows cannot claim one device's serial.
- Record an arrival on the poll that observed it, on that poll's bounded context, and keep an arrival the registry refused owed until it is accepted: a device that arrived and was never recorded is exactly the device the console cannot show, and once it is in the watcher's view the watcher has no second chance to notice it.
- Keep the action-safety boundary in the lease/fencing/policy/control-session kernel, not in the existence of a device row: a device row carries identity and observation history, and confers no authority to act on the device.
- Keep current projections separate from append-only audit, event, observation, and evidence history.
- Treat registry membership as a deletable projection over a durable device identity anchor. Retirement is an attributable, reversible expectation decision rather than a device lifecycle state; a later observation surfaces the still-retired device instead of silently restoring or hiding it. Permanent deletion removes only registry membership after exact-id confirmation and after every live relationship is absent; append-only observations, attempts, evidence, audit, control, and mirror history retain the old identity, while a physical device observed after deletion receives a new identity linked by the deletion record rather than silently undoing the decision.
- Keep ONE current endpoint per device and read that endpoint wherever a surface answers where the device is: an endpoint change is not an identity change, so a device activated onto a new port keeps one identity and one current endpoint, the transport it left becomes superseded at a recorded moment, and it leaves every list and every count while staying readable as that device's own endpoint history. A surface that lists endpoint RECORDS rather than each device's current endpoint draws one device once per address it has answered on, which is how an operator sees a moved device twice on a board. Endpoint CURRENCY is an observation fact and never an authorization decision: a device this plane can see attached is at that transport whether or not the adapter may use it there, so an observation makes its transport current and records beside it the state that transport reported, and an observation a saved-profile scan saw is a sighting whatever its link state — reading an attached-but-unauthorized unit as unseen supersedes the endpoint that records it, which is how a bench of twenty plugged-in units drew as one. Where an action resolves the device to act on, it asks the recorded link state as a separate, fail-closed check and refuses with what the transport reported rather than with a missing transport, so nothing becomes reachable by being visible, and the row that says where a device is stops being the row that decides whether it may be used. An action's CANDIDATE SET is the fleet this plane reads as ONLINE — not the registry: a device is online only while its current endpoint reported a usable link AND that sighting is recent enough to still stand, because a sighting that has stopped standing leaves an address that may since have been handed to another unit. The ONLINE reading is made in ONE place, and it is the same reading the console paints and the same one every action resolves its candidates from, so a surface that shows a device as online and a run that acts on the online fleet cannot disagree about which devices those are. A device that is not online is not a failure of a run: it is excluded from the run, NAMED in its report with a reason of its own (never dropped, and never counted as a device the run contacted or failed against), and the count an operator reads is what the run targeted.
- Offer a device only where an operator could switch to it, and state what was withheld. The set a selector offers is one reading made in one place, resolved from what the plane records about the device's identity and its history — a retired device, the replaced identity a later observation linked by its deletion record, and a device nobody has ever observed are each excluded — while the registry view keeps listing all of them with the state they are in. The exclusion is a property of the SET, not of a row: the surface draws what it offers, names how many it withheld and why, and never becomes a filter over what the registry may show.
- Reference a dispatched device action's outcome by an append-only evidence record, never by its current projection: an attempt row is updated as the attempt moves, so a reference to it names what was intended rather than what happened. The record carries the action identity, the target device, the outcome and the resulting observation, and it has no field in which typed content or a credential could be carried.
- Use explicit state machines for workflows, control sessions, devices, package lifecycle, approval, and recovery states.
- Treat group and placement order as persisted operator order. Never derive it from insertion order, a row id, or a list index; write the whole order, not a single occupied slot, and reach an order by renumbering inside one transaction rather than by overwriting a neighbour's position. A CONSOLE display order is a KEY over persisted facts rather than a stored arrangement of its own: the board's choice is one value (`control_workspace_layout`), every surface resolves the order from that key through one function, and the `placement` key reads this persisted order rather than re-deriving one. A per-device manual console order is retired — it is a second order maintained outside the domain, and it grows with the fleet — so no surface stores one, and a stored one is read as nothing rather than reinterpreted.
- Answer where a device is with the ADDRESS recorded on its current endpoint, and say so when there is none. A device tile, a list row and a reader all take the address from the endpoint record the plane publishes, through one reading (never reassembled from parts, never parsed out of a string), and a device with no current endpoint is reported as having no address rather than as an endpoint id, a device id or a hardware serial — an identifier in an address's place reads as an address and is not one. Keep the two facts distinguishable on the surface that draws them.
- Ungrouping ends a placement. "Ungrouped" is a computed view over devices with no active membership, never a stored group, and a row that append-only evidence references is retired in place rather than deleted.
- Use typed identifiers internally. Never make a mutable serial, IP/port, display name, account label, or UI row number the primary identity.
- Keep every action-catalog entry complete: a typed identity, at least one allow-listed capability, a risk and retry class, the mutating/read-only classification with the reason for it, and an explicit postcondition stating what must be true after a successful dispatch. Refuse an incomplete entry at lookup rather than authorizing it on a zero value.
- A kind that a documented deferral previously refused carries the recorded reason it is dispatchable now: name the deferral's precondition and the record that lifted it, beside the entry, so a reviewer can tell a newly permitted kind from one that was never deferred.
- Discover a transport that attaches after launch by polling the adapter enumeration on a bounded interval, with every poll on its own bounded context, and report what changed as a transport event rather than as a device identity: the adapter's allow-list admits fixed builder shapes only, so a device tracking command would have to be admitted to that allow-list before it could exist at all. Polling is also the resolution — an attachment and a detachment between two polls is not observable — so a watcher says that plainly rather than implying event fidelity.
- Treat an enumeration that answered with nobody as an unreadable observation and never as an absence. A poll that failed, a poll that timed out, and a poll that answered empty are one fact — the adapter's transport list could not be read — so none of them carries a fact about any transport: no departure is recorded from it, and the last readable view stands for the next poll to compare against. Reading an empty answer as "everything left" supersedes every current endpoint in the workspace in one five-second poll and turns an observation failure into a fleet-wide outage that only a later poll that happens to answer can repair, which is what the fleet did for seven minutes on 2026-09-19. Name the condition beside the failed polls rather than totalling it as departures: a fleet that stopped being observable has to be explicable from the watch's own numbers, not only from the absence of new rows. The same rule binds every path that reads the enumeration, and the one path it does NOT bind is the completed saved-profile scan, which is a complete view on purpose (see reconcileMissingEndpoints and TestSavedProfileScanSupersedesCurrentEndpointMissingFromTheScan).
- Never record a departure for a transport the SAME poll observed present. The adapter re-registers a transport's own identifier after a hub mode change or an adapter restart, so one attached transport answers under a second name; a departure names the record it ends by serial and address, which is precisely the record the same poll's arrival has just made current, so the departure would erase the arrival and leave an attached device with no current endpoint at all. Decide it against the poll's own answer — the transport record is present, so the transport has not left — and report the change as a re-identification of the transport's own name rather than as a detachment, while change detection still keys on the transport's identifier so a genuine move and a genuine departure are unchanged.
- Capture a device's screen only for a device something is subscribed to, from one owned worker: a subscription starts and stops the capture, the subscriber set is bounded, one tick captures each subscribed device once on its own bounded context, and a capture larger than the preview bound is reported as truncated rather than delivered as a partial frame. A device whose capture fails stays subscribed with its own classified failure recorded beside the frame it last produced — never a silent success, never a frame a reader can mistake for the device's current screen, and never a reason for the loop to stop capturing every other device. The engine is a bounded still-frame path, not a media transport: it holds one still frame per subscribed device and nothing in it may be presented as continuous video. The fleet GRID is this engine's consumer — its tiles are the stills this engine holds, one per subscribed device at the deployment's level — so the grid's own bound is this engine's sweep bound (a deployment input, not a session count) and its cadence is an AIM the sweep's own duration can overrun: a fleet larger than the cadence can sweep is reported at the cadence the plane MEASURED, per device, rather than at the one it was configured with.
- Draw a fleet grid's tiles as the control plane's STILLS, and never let a tile imply it is live. A tile that shows a device's screen carries the still PICTURE the plane captured on its own cadence, which is a picture and nothing else: it subscribes to nothing, it carries no input path, no lease and no control session, because viewing confers no authority to act on a device. A still spends no device session and holds no encoder, so the grid draws EVERY device it is given — no allocation, no cap and nothing dropped — and this console holds no tile count of its own at all: one LIVE tile was one stream on the plane, which is the exact session the operator's own big frame is kept out of, so a capped grid of live tiles cannot reach every device at any preview level. The only bound left is the plane's own sweep, a bound on its work rather than a place a device waits for, and it is stated in the tile it did not reach rather than as a tile count. The level a tile's still is carried at, the plane's cadence, and the sweep bound are DEPLOYMENT inputs (`DRIFT_GRID_STILL_LEVEL`, `DRIFT_GRID_STILL_CADENCE`, `DRIFT_GRID_MAX_DEVICES`) rather than console settings, and the bound and the level are set from measurement: on the 2026-09-21 lab fleet of 19 attached devices, one still measured 18.7 KB delivered at the medium level (360 px wide, q65) from a 3.4 MB `screencap` (low 9.6 KB, high 30.7 KB), so carrying the whole fleet as stills at a 4 s cadence cost 0.77 Mbps — 1.9% of the 40 Mbps one live operator-profile stream was measured at — while the plane's session count stayed at the operator's own one. What binds the cadence is the CAPTURE and not the transport: one capture took a mean of 3.1-4.2 s over TCP, so a sweep of the whole fleet took 59-71 s and a device's refresh interval is `max(the cadence configured, the sweep itself)`. A deployment reads the cadence the plane MEASURED for each device rather than assuming the one it configured, and the sweep bound is a bound on the plane's own WORK — a full sweep of the bound's worth of devices at the measured capture cost — never a place a device waits in line. The operator's own big frame is separated from the grid by measurement rather than by assumption: the same live session, on the same device, for the same two minutes, carried 45 access units with the grid refreshing all 19 devices beneath it against 34 with no grid at all, and its longest quiet run was 58 s in both arms (evidence: `tests/compatibility/grid/`). The device set the grid names IS the plane's capture set, so the whole set travels on every reconciliation, in the grid's own order, and the console releases it where the grid goes away. A tile that is not CURRENT SHOWS no picture: the last still the plane holds is not the device's screen now, so the tile drops it — leaving its image's source unset rather than painting a screen the device has moved on from — and reports the plane's own state, with the whole sentence carried as that element's accessible name rather than clipped into a hundred-pixel frame. Drop the picture and not the element the picture is written into: mount that element for the whole lifetime of the tile, and let the state that stops the still being current change its source and not its existence, exactly as the big frame does. A read the console could not complete is a fact about the console's REACH and never a report about a device, so it withdraws nothing and claims nothing, and no state the plane did not classify as a failure may borrow the classified failure's words or its alert. And one absent state is ONE colour: a device with no current observation is drawn in a single fixed colour shared by every such tile whatever its index, group or placement, distinguishable from an observed tile's own, with the status label and the absent mark still carrying the fact in words. Draw a tile at the DEVICE's own shape and let the frame take it: the plane states the delivered still's size WITH the picture (its width and height are set only for a CURRENT still), so the picture takes the frame's whole width — no padding and no inset of its own — and the frame is as tall as the device's screen at that width, which is what makes a tile the phone rather than a phone-shaped picture centred in a wider box. A frame pinned to the console's own 9:16 leaves the frame's own colour down both sides of a 9:19 screen, measured 2026-09-21 in a browser: a 360x760 still drew 88 px wide in a 102 px content box — 7 px of frame either side at the console's default 192 px frame — and 48 px in a 186 px landscape box, 69 px either side. A landscape frame is a frame TURNED: the picture keeps its own aspect and is drawn turned to fill it, because a portrait screen laid into a wide frame is otherwise letterboxed or cropped, and a cropped device screen is a frame an operator can mistake for the whole screen. A tile the plane stated no size for keeps the console's own portrait shape, carried by an element mounted for the tile's whole lifetime like the picture's own.
- Arm a live mirror from the deployment's own configuration, and fail where it is configured: the adb executable and the host path of the scrcpy server are absolute deployment inputs, the server's own name is bounded by the allow-list's rule rather than by a second copy of it, and the device-screen hold is an explicit choice (it defaults on, because a sleeping device streams nothing at all). A deployment that can arm the mirror is what supplies those inputs, so the runtime that launches the control plane resolves the server path — a value the deployment configured, as configured even when it is wrong; then an explicit value in the launching environment; then the platform's own scrcpy installation, and only when that file is actually there — hands it over on EVERY start path it has rather than on the one an operator happened to use, passes nothing at all when it resolves none (never an empty value, which is a mirror that arms and shows nothing where no value at all makes the dialer name the input), leaves the screen-hold choice unset so the operator keeps it, and reports what it resolved in a startup line the operator's frame can show. A seam that cannot arm the mirror names the input it is missing, so a host with a frame that shows nothing also has a diagnosis. The live-mirror engine is a media transport and is not the bounded still-frame engine above: it holds one session per device, that session exists only while a viewer is subscribed, and input reaches the device only after the kernel authorizes it and only in the frame the stream is encoded at. Keep that session out of the lifetime of the request that opened it: the operator's request returns before the session's work is done, so a session that inherited its cancellation would have the device's own work — the push of the server, the transport handshake — cancelled mid-flight, end itself, and leave the browser refused the very identity it was just given. The same rule holds one layer down, for the device work the session itself started: a viewer change re-encodes the stream, and a re-encode must never cancel the push of the server or the handshake it did not start — that work belongs to the session, so a viewer that attaches while the device is still being opened is answered by opening the device again once the open already running has settled, never by tearing it down, and a read the session ends to start that re-encode is stated as the session's own cancellation rather than as the device's stream ending. What ends a session is its last viewer detaching for the idle bound, the device's stream ending, or the engine being stopped. Classify every one of those ends in the plane's own closed vocabulary — the last viewer detaching, the engine being stopped, the device's stream ending, the device-side server failing, the transport failing to be established, a device reporting no streamable screen, a push this plane itself cancelled — and state the CLASS beside the sentence rather than the sentence alone, because a surface holding only words derives the state it renders from them: that is how an operator who closed the frame came to be told their own departure had failed, and how a dead device-side server reached an operator in the same sentence as a device that simply stopped. A cancellation this plane performed is never the transport failing: a class that names the wrong layer is a wrong errand, and "the transport to the device could not be established" sends an operator to check a network, a hub and a device that were all working while the fault is local — measured on the lab fleet, where this plane cancelling its own adb push four seconds in was reported exactly that way. An ending is not a failure and the class is what says so; a class stated at the adapter, which is the only layer holding the device's own process, is carried up through every wrap rather than replaced by a class a higher layer assumed; a stream reported FAILED always states why, falling back to the class's own sentence rather than to an empty field; and an engine's own accounting reports how its captures ended, because an end nobody was watching reports to no surface at all. Name the identity in that refusal, and name the identities that ARE carried beside it: one sentence covers an identity that was never a stream, one whose session has ended, and one carried under another name, and a frame that shows nothing is diagnosable only from what it was told — which is also why the console keeps the control plane's sentence rather than replacing it with its own. Bound the launch the way the DEVICE bounds it, and measure that bound rather than assuming it: the device-side server's own command line is what the device's codec stack copies into a fixed buffer while it names the process whose encoder it is configuring, so a launch that runs past that buffer aborts the device's server inside its codec stack before the first frame — which the host sees only as a transport that never came up. On this fleet the bound is 264 bytes for the whole `app_process / com.genymobile.scrcpy.Server <version> scid=<hex> <options...>` line (263 streams, measured one token at a time), so the launch states only the options the admitted server does not already default to, `MirrorLaunchCommandLineLimit` carries the number with its measurement, a launch that would exceed it is refused where it is supplied rather than dispatched to a device, and the length is pinned by a test over every profile, cadence, log level and wake setting this product can build.
- Await a fetched stream's ACCEPTANCE and never the end of its body: on the transport whose response body IS the picture, a start that read that body to its end could not answer while the stream was alive, so the phase the surface shows, the poll that reads the plane's own state, and any report of a picture that never came were all unreachable for exactly as long as the stream was working (ARC-255: a frame sat in `opening` on a live stream and reported nothing to the operator). What is awaited is the endpoint's acceptance — its status read and its first bytes in hand and handed to the media stack — what follows runs in the background and is ended by the session's OWN teardown, and that teardown RELEASES the response instead of leaving it being read, because a reader left pending holds the connection open and leaves the plane writing into a stream nobody is showing. The wait for acceptance is BOUNDED (`defaultMirrorEstablishTimeoutMs`): an endpoint that answers and hands nothing over reaches a reported failure that names the bound, rather than a surface that sits in `opening` — on a first open and on every re-entry alike, because a re-entry the plane cannot establish is the same fact. A body that fails AFTER acceptance is reported through the port the console hands the playback (`onFailure`) rather than swallowed, because half a picture is not a picture.

- Treat a mid-stream re-declaration as a supported event on both sides of the TCP mirror, never as the end of a stream. A live session is EXPECTED to be re-declared — opening a grid tile into the operator's own frame re-dials the device at the operator encode profile, and a device whose screen changed size re-declares on its own — and fragmented MP4 expresses it: `MP4Writer` writes a NEW initialisation segment at the access unit that carries different parameter sets (a new `avcC`, and the size the frames are now encoded at, told to the writer with `SetSize` so the sample entry never states a coordinate frame the pictures are not in) and carries the same byte stream on under it, while the console's player accepts a second initialisation segment mid-stream: it signals a codec change with `changeType` immediately before appending that segment and keeps the picture, never taking the element down or making a second media source for a reconfiguration. A re-sent set that is the one already declared is NOT a re-declaration and writes nothing. The only mid-stream change left as an error is one this container cannot express at all — a codec its `avcC` cannot declare — because there is no declaration to write; ending a stream is the failure this rule exists to remove from the normal path, not the escape hatch for it.

## 3. Control, workflow, and concurrency design

- Selection, health views, event views, and permitted preview are read-only. State-changing control requires an explicit control session.
- Every state-changing device action requires a valid per-device lease, fencing token, idempotency key, timeout, cancellation behavior, postcondition, audit record, and cleanup behavior.
- Enforce one active mutating controller per device. A process-local mutex is only local serialization; it is not ownership protection.
- Device actors serialize commands for a single device. Do not allow concurrent mutating command execution within an actor.
- Reject expired, revoked, stale-fenced, duplicate, ambiguous, unauthorized, or incompatible actions before dispatch.
- Model manual source-and-follower mirroring as typed action fan-out. Each follower has its own lease, actor, policy/capability check, current observation, action attempt, evidence, and result.
- Never blindly mirror raw coordinates, stale UI nodes, raw protocol commands, credentials, or secrets.
- Permit device input as typed, first-class actions (tap, swipe, typed text, key event, app launch) — and, because an operator needs the fleet's real work done rather than a fixed button set, as a general device command. BOTH go through the lease, fencing, policy, control-session and emergency-stop kernel, and neither is ever a raw command string: a command reaches the device adapter as an ARGUMENT ARRAY and is spawned without a shell, so no admitted position is ever parsed as shell text, a metacharacter, a quote or a second command. A general command is admitted in exactly one of two forms. (a) CATALOGUED: a named operation with a bounded, typed parameter set, appearing as an ordinary first-class action with its own audit record. (b) ADVANCED: an operator-entered argument array chosen for this device, which is dispatched only after the operator confirms the EXACT argv to be run, lands an append-only audit record naming that argv, the actor, the device and the outcome, and requires an explicit control session. The advanced form passes arguments to the device without a shell; it does not accept a host-side executable path outside the admitted set, so it cannot read or write arbitrary host files. This rule replaced an earlier blanket ban on a generic command action. The ban was retired deliberately on the owner's instruction (2026-09-17) because it blocked parity with the product this one replaces, which already exposes arbitrary device commands; the kernel, the argv form, the audit record and the advanced form's confirmation are the conditions of that retirement, not optional extras.
- A device input is dispatched only after the kernel authorizes and dispatches it, and a read-only readiness check in front of that is an additional fail-closed gate, never a replacement for it. A refused input reports its own stable reason and failure class (never a generic internal error), reaches no device, and is provably distinguishable from every other refusal. An input whose typed payload is absent, doubled, mismatched to its kind, or measured in another observation's frame is refused before the kernel is asked.
- Name the observation a typed input was resolved from on EVERY kind the catalog declares as requiring one, not only on the kinds that carry a coordinate. The key event is the case that proves it: its request carried a hard-coded empty observation token while the tap and swipe beside it carried the frame's own live stream, so every keystroke and every press of the device's own navigation keys was refused by `Intent.Validate` as a malformed intent — surfacing to the operator as the client message "device input intent is invalid", which names neither the field nor an action — before the kernel was ever asked. A catalogued requirement is satisfied at the layer that CONSTRUCTS the request; the kernel's validation is never relaxed to admit a request that does not satisfy it, and the console refuses locally, in its own words, only the case where it has no observation to name.
- Admit an argument array to the device adapter's allow-list as a fixed builder shape: a specific subcommand of a named device binary, with every variable position either a canonical bounded decimal or a name matching a strict allow-list pattern, and with the bounds re-derived inside the adapter rather than imported from the builder. No admitted position may accept whitespace, a shell metacharacter, a quote, a flag, a path or a second command, so a catalogued array can never express command text. An ADVANCED general command (see the rule above) is the one admission that is not a fixed builder shape: it is a separate recogniser, it is never reachable by selecting an action-catalog kind, it requires an explicit control session, its exact argv is confirmed by the operator before dispatch, and it is refused when the array names a host-side executable path outside the admitted set. Keep it distinguishable from every catalogued admission in a test, so the advanced path can never be reached by a request that meant a catalogued one. Build each form to the grammar the device's own tool accepts for THAT form, and confirm it against the tool rather than against a sibling form: a tunnel removal that appended the addition's target was admitted by the allow-list, refused by adb as a usage error, and left the tunnel registered against a loopback port the process had already closed — a release that reported nothing and removed nothing, which is why a form whose shape is not the tool's own must be refused by the allow-list rather than accommodated by it.
- Give a catalogued settings operation a postcondition the device can be read back for, and evaluate it against that read: a settings change is never reported as applied because a command exited zero. The operation reads the setting off the device after it writes it, and a read the device refused or answered unusably leaves the setting unconfirmed rather than confirmed, so a device that is still rotating is never reported as prepared. That read is the observation the completion names, and it is the one admission whose postcondition is a device SETTING rather than a device observation.
- Get a fleet-wide operation's per-device answer from the lease, not from an aggregate verdict: a device that is under another controller, has no current transport endpoint, or does not read back as required is reported as its OWN row and the run continues, and only a fleet that cannot be read at all stops the run. A device silently absent from the report is the outcome that must not happen, so a registry the operation could not reach a device through is reported as that device's refusal rather than omitted.
- Keep each allow-list admission in its own independently callable recogniser, and keep the admissions disjoint: no argument array may be admitted by two recognisers, each admission carries a distinct operation name, and a read-only admission's operation name is never an action-catalog kind, so it cannot be selected as an operator action. This separation is a safety property, so assert it in a test rather than leaving it to the order in which the recognisers happen to be asked; an admission whose separation cannot be observed by a test is an admission whose separation is only intended.
- Start a long-lived device process through the same allow-list as a bounded command, never beside it: a device process that outlives the call that started it is started by the adapter that owns spawning, which asks the same admission and then requires that process's own operation name, so no shape admitted for a bounded command can be started as a long-lived one. The caller owns the process lifetime — the start context bounds the start alone — and the child gets the adapter's environment allow-list rather than inheriting the host environment, because a process this product starts on a device must not carry variables it never chose to hand one.
- Carry the coordinate frame with the coordinate. A device input that uses coordinates states the render size the device presents at — the `wm size` override, never the physical panel size and never a downscaled screenshot or vision frame — and the observation the coordinates were measured from; a coordinate without a frame, outside it, or bound to another observation is refused, never scaled. The observation a LIVE frame's coordinates are measured from is that frame's own live stream, and never a capture: a pointer is read off the picture the stream carried, in the frame the stream is encoded at, so the stream is the observation the point belongs to. A console that demanded a capture's token instead refused every gesture on a host that had none — and no real-device path records an observation snapshot, so that demand could only ever refuse — while naming a capture would in any case bind the point to a screen the operator did not point at. What makes such a coordinate safe is not the token: the kernel carries it as the frame's own label and the render-space cross-check against the device's `wm size` remains the gate, so a frame the device does not present at is still refused. A frame with no live stream has no observation to measure in, and says so rather than inventing one. A coordinate an operator points at in the console is measured against the box the picture is DRAWN in, never the element's box: the console's own frame is one shape and a device's stream another, so the browser letterboxes the picture inside the element, and a point in the bar left beside it is refused and named rather than scaled onto the frame. Carry that frame through both gates, and never treat one gate as a substitute for the other: the kernel authorizes and dispatches the action, and the render-space cross-check independently refuses a declared frame the device does not present at, so a dispatch must satisfy both. Cross-check the declared frame against the render size the device actually reports before dispatch: a frame the device does not present at is refused with a distinct error naming both sizes and reaching no device; a frame whose device size cannot be read, or whose reading is too old to refresh, is refused too (fail closed, never serve a stale size, never fall through to the transport); and when a device reports both an override and a physical size, the override wins and the resolved value says which it came from.
- Reconcile the observation a typed input names with the STREAM that carries it, at the delivery, and never leave the gate as two strings the caller supplied comparing equal. A live frame's observation is that frame's own live stream, so the token a request carries names the session the input travels on — and the session is the only thing that knows which stream that is. The delivery refuses an input naming any other observation (another device's stream, a stream this device has left, a captured observation, or none at all) with its own stable reason and classified failure, before anything is encoded and before the device is reached, and that refusal is provably distinguishable from the render-space gate's. The transport's check that a render space names its own request's observation is a caller-CONSISTENCY check and is NOT this one; neither is a substitute for the kernel's authorization or for the render space's cross-check against the device's `wm size`, and a typed-text input states no observation because content carries no coordinate.
- Give a device input no generic or incomplete payload path: a mutating input whose typed payload is absent, incomplete, or the member of a different kind is refused at the boundary before authorization.
- Model multi-device automation as one parent run and independent per-device target executions. Resolve a target snapshot at run creation, use bounded concurrency, and retain independent target state, retries, cleanup, and failure results.
- Failures must be classified and visible per target. Do not infer group success from source success or conceal a failed target behind aggregate state.
- Treat an address served by a process this session did not start as a condition the operator resolves, never as a dead end: name the holder (pid, and the command where the platform can tell us) wherever the condition is reported, and offer adopting that process or terminating it per address. Never choose either silently — silent adoption is the stale-binary hazard, and silent termination can destroy a service the operator started deliberately. Adopting records a decision and states that the process's revision is UNVERIFIED; it starts and stops nothing, and a component adopted is never reported ready. Terminating signals only the holders that were identified, one process at a time rather than a process group, refuses a pid it must never signal (init, a whole group, this session itself), verifies the address is free before starting anything, and starts nothing when it is not. Making no choice changes nothing and is not a failure.

## 4. Go standards

### Code design

- Use idiomatic Go: small packages, exported identifiers only when needed, clear names, and concise package documentation for non-obvious domains.
- Pass `context.Context` through request, workflow, storage, and adapter boundaries. Honor cancellation and deadlines.
- Use typed domain errors or stable error codes at API boundaries. Wrap underlying errors for diagnostics without exposing internals to clients. When a failure cannot be classified, keep the generic client message but record it server-side with the operation, the error class, and a redacted, bounded diagnostic instead of leaving only the generic message.
- Keep side effects behind narrow interfaces so deterministic fakes can exercise application behavior in tests.
- Do not use `panic` for expected application failures. Return errors and classify them.
- Do not start unowned goroutines. Every background worker needs an owner, cancellation path, bounded work queue, error handling, and shutdown behavior.
- Own a live capture the way the process owns its listener, and audit it before returning: the live mirror engine is constructed once by the composition root, cancelled by the same shutdown context as the listener, stopped under a bounded timeout on that shutdown, and awaited before the process returns, so no session, goroutine or device-side process outlives it. Bound the session's own release as well as the wait for it, and name the device a bound expired on rather than waiting without end: an operator can act on a reported device and cannot act on a hung process. Report what was started and stopped from the engine's own accounting instead of assuming `Stop` returning meant nothing was left, and where that accounting disagrees with itself say a device-side server or its tunnel may still be there. An engine that could not be constructed states why in the startup line rather than existing and showing nothing.
- End every supervised session on every path, and make the record say which path ended it: one ending states the session's state, the class of the end in the plane's own closed vocabulary, and the cause, and the state may never contradict what that class says about whether the end was a failure. A session that only the caller which happens to remember can finalise is a session every other caller leaves active, and a row reporting running work that is not running is a record an operator and a later reader cannot trust. A record a process started and never finished is repaired by the next process at startup, bounded by the moment that process started so the repair cannot close a session something else is carrying, named in the startup line rather than silently closed, and never deleted: the repair is a state, not a deletion. An ending its own request was aborted out of is written again on a context the abort cannot cancel, bounded, so an abort ends a session rather than orphaning it.
- Use structured logging with operation, correlation ID, device/run/target IDs, duration, result, and failure classification where relevant. Never log secrets or full sensitive payloads.

### Data access and transactions

- Keep SQL close to repository implementations; make queries explicit and reviewable.
- Keep transactions short. Never hold a transaction while waiting on device, network, filesystem, or user-interface work.
- Application services define transaction scope for state transitions that must commit atomically with audit and outbox records.
- Check and return affected-row results for conditional updates such as leases, fencing, optimistic concurrency, and state transitions.
- Use database constraints for durable cardinality and uniqueness invariants; do not rely only on application-side checks.

### Terminal surfaces

- Keep terminal surfaces safe to leave. Restore terminal state on every exit path, including normal exit, error exit, signals, and panics; never leave an operator's terminal in a modified state.
- Emit raw ANSI escape sequences only when stdout is a terminal and `NO_COLOR` is unset. Write no escape sequences when output is piped, redirected, or captured.
- Detect the terminal width and bound every region the surface redraws. Do not assume a fixed size, and do not let a redrawn region grow without limit.
- Make what the surface draws agree with what it says. A numbered action list ascends in reading order and down each grid column, and the key that leaves the surface is the last one drawn, so an operator counting down the list cannot find more work after the way out. A key that is a convention rather than an action is offered without a number and named in the frame's own key legend, never offered unexplained. A classification an operator has to act on — a key that reads state against one that changes what is running — is drawn as a glyph that the same legend explains, never left to colour.
- Bound a region without losing what is in it. A region's height may be fixed so a chatty source cannot push the frame around, but text that does not fit is wrapped onto a marked continuation row or ended with an explicit ellipsis, and the rows a region cannot show are replaced by a notice naming how many were withheld and where the whole text can be read. The surface a notice names must carry the text it is named for: a notice that points at a region which shortens the same line ends the operator's search somewhere worse than the notice did. A shortened line that does not say it is shortened is the same defect as a lost one.
- Separate rendering from input handling so layout and colour behaviour can be tested without a terminal.
- Prefer the least invasive rendering that still produces a stable frame. Do not take the alternate screen or hide the cursor without a reason.

## 5. SQLite and local artifacts

- SQLite is owned by the Go service. UI processes and packages never open or write the database directly.
- Enable foreign keys on every connection. Use WAL mode and a bounded busy timeout.
- Use explicit transaction boundaries. Use a write reservation appropriate to the driver for lease/fencing transitions that require exclusive write intent.
- Store timestamps consistently in UTC using one documented representation. Store internal IDs as validated text UUID/ULID values.
- Read an append-only history in append order — the table's own insertion order — not by its recorded timestamp: two appends can share one timestamp, and a history whose order ties cannot be read in order.
- Keep JSON payloads bounded, schema-versioned, and exceptional; use relational columns for relationships and queryable facts.
- Use forward-only ordered migrations and a migration ledger with version/checksum tracking. Do not edit a shipped migration; create a repair migration.
- Processes that share one database can run at different revisions, so a binary must refuse to start when the applied ledger holds a version newer than the migrations embedded in that binary. Fail loudly, name both versions, and never serve requests against a schema that moved on.
- Test fresh installs, upgrades, interrupted migrations, dirty-state recovery, foreign-key enforcement, contention, and backup/restore.
- Store artifact bytes in a private content-addressed filesystem store. Store only metadata, hash, size, retention, and references in SQLite.
- Write artifacts atomically: write temporary file -> verify/hash -> atomic rename. Never authorize arbitrary paths from stored metadata or UI input.

## 6. Protobuf, Buf, and Connect

- Define public messages and services under `proto/drift/v1/` using additive evolution by default.
- Never reuse field numbers. Do not rename/remove published fields, enum values, or RPCs without a compatibility and migration strategy.
- Keep request/response messages explicit; avoid generic map payloads for stable domain APIs.
- Carry a typed action's payload in a `oneof` whose members are named for their kind, one member per kind, and refuse a payload that is absent, incomplete, or belongs to another kind at the transport boundary — before the kernel is asked to authorize it. Grow the oneof additively; never reuse a field number. A member that carries a catalogued operation carries only its bounded typed parameters. A member that carries an ADVANCED general command carries an ARGUMENT ARRAY — a repeated string of discrete arguments, never a single joined command string — so the value can be spawned without a shell and each argument is visibly separate in the audit record. That member is the only exception to the rule that no payload carries caller-supplied command text; it exists because the owner retired the blanket ban on a general command action (2026-09-17) and it carries that action's conditions with it: an explicit control session, operator confirmation of the exact argv, and an append-only audit record naming the argv, actor, device and outcome.
- Validate contracts with `buf lint` and `buf build`.
- Regenerate code with `buf generate` when contracts or generator configuration change. Never hand-edit generated files under `gen/` or `apps/console/src/gen/`.
- Keep transport handlers thin: authenticate/authorize, validate input, call an application service, and map known errors to stable typed responses.
- Mount Connect services explicitly as `service.Route` values passed to `service.NewHTTPServer`. Never mount handlers by reflection or package initialization, and never mount a route whose application service was not constructed.
- Treat transport/API errors as contracts: stable codes and safe user-facing messages; no database, filesystem, device, or stack-trace leakage.
- Map a classified failure by resolving the whole error chain (`errors.As`), not by a direct type assertion: a platform error wrapped for diagnostics with `%w` keeps its stable code and safe message, and the generic internal fallback still answers failures that carry no classification.

## 7. React, TypeScript, Vite, and Tailwind

### TypeScript and state

- Keep TypeScript strict. Do not use `any`, `@ts-ignore`, unchecked casts, or untyped service payloads. Narrow `unknown` at every untrusted boundary.
- Use function components and hooks. Keep presentational components, feature components, data hooks, and domain/API types separated.
- Use TanStack Query for service/server state. Use component state for transient UI state only. Do not duplicate authoritative service state in ad-hoc global stores.
- Validate complex forms and untrusted input with Zod. Keep validation rules close to the type/feature that owns them.
- Keep effects focused and cleanup-safe. Do not use effects as a substitute for derived state or event handlers.
- Preserve the existing `@/` import alias and avoid deep relative imports when a module boundary is clearer.

### UI composition and accessibility

- Use shadcn/Base UI primitives through composition. Prefer class/token composition over duplicating primitive behavior.
- Keep components small and focused. Extract a component when it owns a meaningful UI concept, behavior, or accessibility boundary—not simply to reduce line count.
- Follow the established visual system: visible rules/separators, square geometry, restrained status color, flat surfaces, and no glow, gradients, glass, backdrop blur, or decorative shadows.
- Use semantic HTML first. Every interactive element must be keyboard-accessible, have a visible focus state, and expose an accessible name.
- Do not convey status by color alone. Include text, iconography, or other non-color signals.
- Support loading, empty, error, disabled, retry, narrow-screen, keyboard-only, and reduced-motion states as part of normal feature completion.
- Put a control's explanation on the control, as a Tooltip whose trigger is the control itself, rather than in a paragraph beneath it: a focusable trigger makes the explanation reachable by keyboard instead of by hover alone, and the copy beside a control is part of the control, so a copy change moves in the same commit as its app test.
- Give a mirrored device's screen the whole frame, and move its chrome to the controls that own it. The element that carries a device's live picture holds the picture and the pointer surface and nothing else: no state line, no transport line, no coordinates paragraph, no key or text controls, no stop button, no footer sentence. Those are not deleted — the device commands live in the panel's action column, which is a separate surface from the frame, and the stream's state, transport, encoded frame, drawn box and every refusal live behind an info control in the panel's title bar, beside the pin, whose tooltip NAMES what it opens. Take the frame's aspect from the stream the frame is carrying rather than pinning the console's own shape, so the picture is not an inset in a dark box, and keep the drawn-box mapping honest so pointer input still lands where the operator pointed. A refusal or a failure is never silent just because it left the frame: the info control marks itself while it holds something unread, and it names the fact rather than the console's own support. Chrome over a mirrored screen is chrome over the thing the operator is reading.
- Give a mirrored device's screen the operator's own keyboard, and make its focus the boundary. The frame is the thing an operator clicks to type, so it is focusable and a pointer press on the picture focuses it, and the keystroke it then receives is a typed key event dispatched through the same lease, policy, control-session and refusal path as the panel's key controls—never a raw command, a new admission, or a bypass—with a refusal reported by its own reason rather than dropped. A key the one-key-code contract cannot carry is refused BY NAME rather than sent as the bare key: one `KeyEventInput` carries one key code and no modifier state, so a modifier held with another key is a keystroke this console does not have, while the modifier keys themselves are keys the vocabulary can name. The gate is the frame's focus, read at the moment the keystroke arrives rather than from one render behind it, so a keystroke that arrives while the frame does not hold focus reaches no device and one typed elsewhere in the console is not captured here. State the capture state where the keyboard controls are—in the panel's action column, never over the device's screen—and make leaving capture one explicit, named control that is this console's own action, so no refusal a device or the control plane reports can swallow it, while Tab stays with the browser because its focus movement is the one way a keyboard-only operator can leave the frame. Bound a held key's auto-repeat by the rate the console gives that control session rather than by how fast the browser emits events, and drop a repeat inside that bound rather than queueing it.
- Derive a field that mirrors another control's value instead of storing it, and render the mirrored part disabled: a derived mirror follows its source by construction and cannot be edited, while a stored one can disagree with it and is only ever one edit away from doing so.
- Render a control only when it performs its action: it either runs the operation and reports the true outcome, or it is not shown. Never gate a destructive confirmation on an operation the service cannot execute, and never render a tab, panel, or section without a backing read path—an empty shell is worse than an absent one.
- Name the cause the operator can act on. A surface that cannot do what it was opened for because the device has no current observation states that observation and the action that records one—a scan—and never renders the missing observation as a transport, a capability, or any other support the console does not have: an operator sent looking for console support the console already has never observes the device. "Never observed" and "observed before, not now" keep their own sentences and their own action, read from the status module rather than restated here.
- Re-read the control plane's projection on a bounded schedule while the console is open, not only on mount and after a mutation: a device that attaches after launch reaches the console because the service records it and the console reads it, so an operator action is never what makes a device appear. A scheduled read is of state the service already holds—it must not raise the loading state or report an outage it did not find—and it is cancelled with the console that owns it.
- Separate a read the console could not complete from a report about what it was reading, and never act on the first as though it were the second. The live stream is the case that proves it: the plane is the only authority on whether a stream is alive—its state is derived from the frames the stream has CARRIED—so a read that cannot be completed is retried on a BOUNDED backoff (the poll cadence, doubling, capped) and leaves the stream ALONE: no teardown, no picture taken down, and above all no stop, because on this plane a session's last viewer detaching is what ENDS the session, and two consecutive failed polls of a busy control plane destroyed a working stream that the operator read as the picture crashing. Only the plane's own `failed`/`ended` state ends a stream, and it is reported in the plane's own sentence. A stop is issued for exactly three reasons—the plane's own answer about that stream, the operator's own close, and a stream this console opened and never carried a picture on (the place goes back rather than being left capturing a device nobody watches)—and a transport fact is none of them. What the console says while it cannot read is its OWN state and not one the plane can report: it stops claiming the stream is live, keeps the picture the stream is carrying in place, names the fact where an operator reads state (the frame shows nothing over a held picture, and its info control marks itself), and asks again. A stream the plane no longer knows—a restarted plane holds no session this console opened—is RE-ENTERED rather than reported: the console opens the same device's stream again, which the plane resolves to the session it already carries or starts one, so a device re-opened after a restart resolves to a working stream and never to a dead frame or a permanent failure. Bound the re-entry (each open spends a place of the plane's capacity) and report a plane that hands out an identity and forgets it, rather than asking forever.
- Use Skeleton components for layout-preserving loading states and avoid unnecessary layout shift.

## 8. Tauri and Rust

- Keep Tauri as a desktop shell and local integration boundary. Business rules, persistence, workflow execution, and device control belong in the Go service.
- Apply least privilege to capabilities, commands, plugins, CSP, filesystem access, shell/process access, and network access.
- Add a Tauri permission, command, plugin, CSP exception, or external connection only for a specific feature with a documented threat model and tests.
- Do not give the renderer unrestricted shell, filesystem, process, network, or device access.
- Keep Rust dependencies minimal, maintained, and pinned. Avoid adding a plugin when a narrow existing capability or Go-service endpoint solves the need.
- Run Cargo/Tauri checks after changing `src-tauri`, `Cargo.toml`, capabilities, or `tauri.conf.json`.

## 9. Security, privacy, and package trust

- Do not commit, log, render, or place secrets in tests, fixtures, screenshots, artifacts, workflow definitions, or documentation. Use `[REDACTED]` where a placeholder is necessary.
- Never put text content in a message field. A generated message renders every populated field in its string, text, JSON and debug forms, so a plaintext field is logged, rendered in an error, and persisted the first time anyone formats it. Reference the value with an opaque, pattern-checked handle and release it at dispatch through the boundary that owns it.
- Operator-supplied content enters the process as a request body on a local guarded surface, never as a field of a generated message. protobuf-go has no per-field redaction, so a message field renders in every one of those forms, and a pattern-matching redactor cannot recognise content with no credential shape: measure the renderings before promising they are hidden. The boundary that admits content bounds the body and refuses an oversize one rather than truncating it (a prefix is the wrong content, delivered silently), keeps no copy on a request, a handler or a cache, logs no request, answers refusals with fixed sentences, and hands the value to a store that releases it at most once. A payload type that carries metadata and no field for the content is the stronger guarantee: it cannot render what it cannot hold.
- Bind local service listeners to loopback or use narrow local IPC. Do not broaden network exposure without authorization, authentication, and a threat model.
- Validate all untrusted input at the service boundary. Prefer typed schemas, allow-lists, and parameterized queries/argument arrays over string commands or shell interpolation.
- Redact sensitive values before persistence, telemetry, errors, audit records, and artifacts.
- Workflows are declarative, typed, and versioned. Skills/packages declare manifests, compatibility, capabilities, fixtures, validation, trust state, rollback behavior, and audit records.
- Packages never receive direct database handles, unrestricted filesystem access, raw device protocol access, arbitrary shell access, credentials, or the ability to bypass policy, leases, fencing, audit, or redaction.
- Do not execute arbitrary downloaded code or implicit dependency installers as a package capability.

## 10. Testing and verification

- Add or update deterministic tests for behavior changes, regressions, edge cases, failure handling, and safety invariants.
- Keep a console UI test's wall time bounded by its own assertions rather than by real-timer waiting, and keep one assertion's cost out of another's budget. `userEvent.setup()` waits on a real timer between the events of every interaction, so a console UI test sets `delay: null` unless the delay is itself under test: measured on a loaded host, a walk over ten destinations spent ~9s of an ~11s test waiting between events and ~2s without them, and that wait is the term that grows with machine load while the render does not. Two consequences. Do not assert many independent navigations in one test — that test pays their summed cost under a single 5s timeout, so one slow destination fails every assertion in it, while one destination per test costs one navigation. And do not let the delay stand in for a lazily-imported page resolving: after a route change, await the destination with a `findBy*` query, because the shell shows its loading state until the module resolves, and a synchronous query there passes only by accident of timing.
- Prove an assertion bites by injecting a fault, and inject it against a **clean tree**: commit the implementation first, or copy the file aside. Never undo an injection with `git checkout --` on a file that holds real work — that restores HEAD, not "the file before the fault", and it destroys the implementation along with the injection. Two separate incidents in one day lost uncommitted work this way. After recovering a file that was clobbered, verify the diff is the change you intended before committing it, rather than assuming the re-application was faithful.
- A fake that answers at once cannot catch a hang: a case for a wait the code is supposed to bound uses a fake whose operation NEVER settles, and drives the wait through the seam the code already schedules on (the console's `MirrorSchedule`) so the bound asserted is the one that ships. Every TCP case in the live-mirror suite faked a `start` that resolved instantly, which is why an `await` on a body that never ends was invisible to all of them; the case that catches it is the one whose fake never answers. The same rule for the fake that answers the contract: a port a teardown now uses has to be answered by every fake of it, or the teardown throws where the real one would release.
- Assert the READING, not the row the reading is derived from. A test that a device kept a current endpoint, or that a transport is still attached, does not test that it reads ONLINE: ARC-146 was opened for a device with a live observation that still derived OFFLINE, and a presence assertion passes on exactly that tree. Every arrival/departure test asserts the wire status the operator is shown, with the presence assertions kept beside it rather than in place of it.
- Prefer fakes for clocks, IDs, transport, filesystem, package runtime, and device adapters. Keep fixtures sanitized and minimal.
- Test negative paths: stale fencing tokens, lease conflicts, duplicate delivery, cancellation, timeouts, failed postconditions, target incompatibility, ambiguous state, migration interruption, and recovery.
- Use contract tests for protobuf/Connect changes, integration tests for SQLite/repositories, component tests for UI behavior, and end-to-end tests only for critical operator flows.
- Run the smallest relevant checks during development and all applicable checks before completion:

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build

go test ./...
go vet ./...

buf lint
buf build
# Run after proto or generator configuration changes:
buf generate

git diff --check
```

- Run Tauri/Cargo verification after shell changes:

```bash
pnpm --filter console exec tauri build --debug --no-bundle
```

- Do not claim test, build, performance, reliability, or security results without actual tool output.

## 11. Dependency and maintenance discipline

- Use `pnpm` and keep the lockfile in sync. Do not substitute npm or yarn.
- Add a dependency only when the existing platform or current dependencies cannot solve the problem cleanly.
- Before adding a consequential dependency, evaluate maintenance activity, security history, compatibility, bundle/runtime cost, licensing, upgrade path, and removal path.
- Prefer maintained, small, compatible libraries. Remove unused dependencies and avoid duplicate abstractions.
- Do not add infrastructure for imagined scale.
- Update this file in the same change when a durable, reusable coding or architecture rule is introduced, corrected, or retired. Keep each rule concrete and technology-specific; do not add temporary task notes or project-management instructions.
